# Pipeline Overview

This project is a two-stage pipeline for binary classification of intracranial aneurysms from 3D MRA imaging data. Raw DICOM archives are first standardised into resampled NIfTI volumes (and 2D representations), then used to train and evaluate CNN classifiers.

Both stages are thin project-specific wrappers around two reusable libraries:
- **[medprep](https://github.com/bruno-schenberg/medprep)** — medical image preprocessing (DICOM I/O, NIfTI conversion, resampling, MIP, QC primitives)
- **[dlorchestra](https://github.com/bruno-schenberg/dlorchestra)** — DL experiment orchestration (k-fold CV, training loop, metrics/artifacts, model registry)

```
Raw DICOM archives (.zip)
        |
        v
+-------------------+
|    Data Engine    |  Extracts, validates, converts, resamples, generates 2D representations
+-------------------+
        |
        v
NIfTI datasets + 2D MIP arrays
        |
        v
+---------------------+
|   Training Engine   |  Trains and evaluates classification models
+---------------------+
        |
        v
Experiment results (weights, metrics, plots)
```

## Stage 1 --- Data Engine

The data engine is a modular pipeline split into four steps. Each step is an independent package under `data_engine/steps/` that reads the previous step's CSV output and appends its own columns. Steps have zero cross-dependencies.

Entry point: [`data_engine/scripts/run_pipeline.py`](data_engine/scripts/run_pipeline.py)

Configuration: [`data_engine/config.py`](data_engine/config.py)

Design document: [`docs/data_engine.md`](docs/data_engine.md)

### Step 0 --- Extract, discover, name
**[`data_engine/steps/step0/`](data_engine/steps/step0/)**

Orchestrated by `step0_discover.py`, which calls three operations in sequence:

**Extraction** (`medprep.discovery.extract_archives`) --- Extracts `.zip` archives from the source directory to a flat staging root. Idempotent: marker files track which archives have already been extracted. Raw data is never modified or deleted.

**Discovery** (`medprep.discovery.discover_exams`) --- Walks the staging root alphabetically. Every folder containing DICOM files (directly or one level down) is a candidate exam. Each folder is classified as `ready` (DICOMs present, no conflicting subfolders), `review_duplicate` (DICOMs in multiple locations), or `empty` (no DICOMs found).

**Naming** ([`naming.py`](data_engine/steps/step0/naming.py)) --- Project-specific wrapper around `medprep.ids.assign_sequential_ids`. Regex-extracts the numeric ID from messy folder names and normalises to `BP####`. Duplicates get alphabetical suffixes (`BP0024A`, `BP0024B`). Synthetic gap rows are appended for every BP number absent from the parsed `min..max` sequence.

**Output:** `step0_discover.csv` --- one row per exam (including gap rows), with columns for original name, DICOM path, folder status, parsed exam ID, and name parse status.

### Step 1 --- Metadata, QC, convert
**[`data_engine/steps/step1/`](data_engine/steps/step1/)**

Orchestrated by `step1_convert.py`, which reads `step0_discover.csv` and runs four modules:

**Metadata join** ([`metadata.py`](data_engine/steps/step1/metadata.py)) --- Wrapper around `medprep.metadata.join_metadata`. Left-joins `dataset/dataset.csv` (user-provided, not included) on exam ID. Adds class label (0 = healthy, 1 = aneurysm), patient demographics (age, gender), and scanner metadata (brand, field strength). `dataset.csv` is the single source of clinical ground truth; it is never generated by code.

**DICOM QC** ([`qc.py`](data_engine/steps/step1/qc.py)) --- Uses `medprep.qc_checks` for scanner-agnostic per-series checks (spacing, extent, orientation, scout filtering) and adds project-specific GE MRA series-selection tiers on top. A single derived column `qc_block_reason` consolidates all conversion blockers as a comma-separated string, or `None` if the exam is eligible.

**NIfTI conversion** ([`converter.py`](data_engine/steps/step1/converter.py)) --- Calls `medprep.nifti_convert` for DICOM-to-NIfTI conversion (MONAI `LoadImage` with `ITKReader`) and centroid-based XY cropping to a uniform 180 mm field of view. Output: `nifti/<class>/<exam_id>.nii.gz`. Runs in parallel via `ProcessPoolExecutor`.

**Resolution grouping** ([`grouping.py`](data_engine/steps/step1/grouping.py)) --- Assigns each converted exam to one of eight resolution groups based on matrix size and voxel spacing, used for downstream QC and analysis.

**Output:** `step1_convert.csv` --- one row per exam with all QC columns, conversion status, and resolution group. `mixed_series_report.csv` --- one row per series in mixed-series folders, with a `selected` boolean.

### Step 2 --- Resample to dataset variants
**[`data_engine/steps/step2/`](data_engine/steps/step2/)**

Orchestrated by `step2_resample.py`. Calls `medprep.resample.run_resampling` to resample NIfTI files to target variants. Because every NIfTI is a uniform 180 mm XY field of view after the centroid crop, spacing is simply `180 / dim`.

| Variant | Shape | Spacing (mm/voxel) | Output path |
|---------|-------|--------------------|-------------|
| `iso_128` | 128 x 128 x 128 | 1.40625 | `datasets/iso_128/<class>/<exam_id>.nii.gz` |
| `iso_256` | 256 x 256 x 256 | 0.703125 | `datasets/iso_256/<class>/<exam_id>.nii.gz` |

**Output:** `step2_resample.csv` --- one row per (exam, variant), with actual spacing and pad/crop percentages.

### Step 3 --- Visual QC
**[`data_engine/steps/step3/`](data_engine/steps/step3/)**

Renders a multi-stage figure showing DICOM, NIfTI, iso_128, and iso_256 side by side for one exam per resolution group. Uses `medprep.visualize` for mid-slice loading and percentile normalisation.

**Output:** `step3_visualize.png`

### Step MIP --- 2D representations
**[`data_engine/steps/step_mip/`](data_engine/steps/step_mip/)**

Generates 2D image representations from 3D volumes for 2D classification experiments. Uses `medprep.mip` for volume loading, projection, and resizing.

| Script | Representation |
|--------|---------------|
| `generate_mips.py` | Standard MIP (axial, coronal, sagittal projections) |
| `generate_topcrop_mips.py` | MIP of top Z% of the volume |
| `generate_thinslab_mips.py` | Thin-slab MIP (multi-slab average) |
| `generate_multiangle_mips.py` | Multi-angle rotated MIP |
| `generate_frangi_mips.py` | Frangi vesselness MIP (project-specific, GPU-accelerated) |
| `generate_lausanne_mips.py` | MIP for external Lausanne dataset |
| `merge_datasets.py` | Combine multiple MIP datasets |

## Stage 2 --- Training Engine

Entry point: [`training_engine/train_models.py`](training_engine/train_models.py)

Reads experiment definitions from a JSON file, merges each with `DEFAULT_CONFIG` from [`config.py`](training_engine/config.py), and runs them sequentially. Completed experiments (identified by the presence of `summary.json`) are skipped on rerun.

### Data loading and splitting
**[`training_engine/src/data.py`](training_engine/src/data.py)**

`get_data_list` scans the dataset directory for `.nii`, `.nii.gz`, and `.npy` files in `0/` and `1/` subdirectories. Each file becomes a record with an `image` path, an integer `label`, and a `path` filename (preserved through transforms for per-sample prediction logging). When `USE_MULTIMODAL=True`, age and gender are loaded from `dataset/dataset.csv` and attached as a float32 array.

Splitting uses `dlorchestra.splitting.split_data`: a stratified hold-out test set (default 15%) is reserved before cross-validation. The remaining development set is either split into a single train/val pair or passed through stratified k-fold cross-validation (default 5 folds), depending on `USE_KFOLD`. Scanner-based stratification groups are provided via `AneurysmExperiment.get_stratify_group_fn()`.

```
All data (100%)
+-- Test set (15%) --- held out; evaluated once per fold with the best checkpoint
+-- Development set (85%)
    +-- K-fold CV (default 5 folds), or
    +-- Single train/val split (default 80/20)
```

### Normalisation and transforms
**[`training_engine/src/data.py`](training_engine/src/data.py)**

Three normalisation strategies are supported, selected via the `normalization` config key:

| Strategy | Method |
|----------|--------|
| `percentile` | Clip foreground to [p1, p99], scale to [0, 1] |
| `zscore` | Z-score normalisation of foreground voxels |
| `histogram` | Histogram matching to a reference template |

MONAI dictionary-based transforms handle loading, channel insertion, normalisation, and (for training folds only) stochastic augmentation:

| Transform | Training only | Parameters |
|-----------|:---:|------------|
| `LoadImaged` | | Load `.nii.gz` from disk |
| `EnsureChannelFirstd` | | `(D, H, W)` to `(1, D, H, W)` |
| Normalisation | | Per config (see above) |
| `EnsureTyped` | | Convert to PyTorch tensor |
| `RandFlipd` | x | `prob=0.5`, all 3 axes |
| `RandRotate90d` | x | `prob=0.5`, max 3 rotations (discrete only) |
| `RandScaleIntensityd` | x | `prob=0.5`, range 0.1 |
| `RandZoomd` | x | `prob=0.3`, 0.9--1.1x, keep size |
| `RandGaussianNoised` | x | `prob=0.2`, std 0.05 |

Only discrete 90-degree rotations are used --- continuous rotation introduces interpolation artifacts on axis-aligned MRA data.

### Class imbalance handling
**[`training_engine/src/data.py`](training_engine/src/data.py)**

Three strategies, selected via the `balancing` config key:

**`weighted_cost_function`** --- Inverse-frequency class weights computed from the training fold, passed to `CrossEntropyLoss`. Weights are computed per fold to prevent label leakage.

**`oversampling`** --- `WeightedRandomSampler` oversamples minority-class examples so each mini-batch sees a balanced class distribution on average.

**`none`** --- No rebalancing.

### Model construction
**[`training_engine/src/models.py`](training_engine/src/models.py)**

Registry-based factory built on `dlorchestra.registry.Registry`. `get_model(name)` looks up the registry and returns a configured model. Adding a new architecture requires one `_reg()` call. All 20 model architectures are project-specific and live in this file; the registry pattern itself is from dlorchestra.

When `USE_MULTIMODAL=True`, `MultiModalWrapper` wraps the CNN: the backbone outputs a feature vector, a small MLP processes tabular input (2 features to 16-d), and a fusion head maps the concatenated vector to class logits.

### Training, evaluation, and orchestration
**[`dlorchestra`](https://github.com/bruno-schenberg/dlorchestra)** (library) + **[`training_engine/src/experiment.py`](training_engine/src/experiment.py)** (project wrapper)

The training loop (`dlorchestra.training`), evaluation (`dlorchestra.evaluate`), and experiment orchestration (`dlorchestra.experiment.TorchExperiment`) all live in the dlorchestra library. Key behaviors:

- **Training**: `train_one_epoch` runs one pass over the training DataLoader with AdamW, optional gradient accumulation, and AMP (bfloat16 on CUDA). `validate_one_epoch` computes loss, accuracy, F2-score, and AUC.
- **Checkpoint selection**: The best model is saved based on **F2-score** (configurable via `CHECKPOINT_METRIC`; the final-campaign configs use `val_auc`). F2 weights recall twice as heavily as precision, reflecting the clinical cost asymmetry.
- **Early stopping**: Training halts if the checkpoint metric does not improve for `EARLY_STOPPING_PATIENCE` epochs.
- **Learning rate schedule**: CosineAnnealingWarmRestarts (default) or none.
- **Best weights restored** before the function returns.

`AneurysmExperiment` ([`src/experiment.py`](training_engine/src/experiment.py)) is a ~100-line subclass of `TorchExperiment` that supplies only the project-specific hooks: model registry, dataloaders, dataset paths, scanner-distribution stratification, and MONAI warning suppression.

### Output tree

Per-fold artifacts saved to `experiments/<name>/fold_<n>/`:

| File | Description |
|------|-------------|
| `checkpoints/model_best.pth` | PyTorch state dict of the F2-optimal checkpoint |
| `checkpoints/metadata.json` | Epoch number and metrics of the saved checkpoint |
| `predictions.csv` | Per-sample filename, true label, predicted label, probability |
| `metrics.csv` | Fold-level AUC, precision, recall, specificity, F2, accuracy |
| `plots/cm_raw.png` | Raw count confusion matrix |
| `plots/cm_normalized.png` | Row-normalised confusion matrix |
| `plots/roc_curve.png` | ROC curve with AUC |

After all folds complete: `evaluation_summary.csv` (per-fold + mean +/- std) and `summary.json` (experiment completion marker, written last).

## Optional Feature --- Tabular Metadata Fusion

The pipeline supports fusing patient metadata (age, gender) with image features using a **late-fusion** architecture. This is controlled by the `USE_MULTIMODAL` config key.

```
experiments.json (USE_MULTIMODAL=true)
        |
        v
data.py: get_data_list(..., use_multimodal=True)
  -> attaches float32 [age/100, gender] to each record under "tabular"
        |
        v
models.py: get_model(..., use_multimodal=True)
  -> wraps CNN in MultiModalWrapper
        |
        v
dlorchestra.training: train/validate
  -> detects "tabular" key in batch at runtime
  -> calls model(image, tabular) instead of model(image)
```

### Architecture --- `MultiModalWrapper`

```
image --> CNN backbone (classifier stripped) --> image features (e.g. 512-d)
                                                        |
                                                        v
                                                  concat --> fusion MLP --> logits
                                                        ^
tabular --> small MLP (2 -> 16-d) ---------------------+
```

The tabular branch is intentionally shallow (two linear layers, 16-d output) to avoid overfitting on only two input features. The fusion head maps the concatenated vector through dropout to class logits.
